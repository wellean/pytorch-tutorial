Optimizing tool selection...先直接解释你这段里 `ToTensor` 的作用，并顺带说明它和后面的 `Normalize` 有什么区别。`transforms.ToTensor()` 的作用是把图像从 PIL Image 或 numpy 数组转换成 PyTorch 张量。

它会做两件关键的事：

1. 把数据维度从 HWC 变成 CHW，也就是从“高、宽、通道”改成“通道、高、宽”。
2. 把像素值从 0 到 255 归一化到 0 到 1，并转换成 float32。

所以你后面这句：

```python
img_tensor = trans_totensor(img)
```

得到的不是原始图片了，而是可以直接喂给 PyTorch 模型、也可以传给 SummaryWriter 的张量。你后面的 `Normalize` 则是在 `ToTensor` 的基础上再做标准化，把数据按指定均值和方差进一步缩放。

GitHub Copilot:
这段里数据和数据类型主要经历了两次变化。

先看原始图片。`Image.open(img_path)` 读进来的是一张 PIL 图片，本质上还是图像对象，不是 PyTorch 张量。它内部像素通常可以理解为 8 位整数，RGB 每个通道的取值范围是 0 到 255，形状如果展开来看一般是 高 × 宽 × 通道。

经过 `transforms.ToTensor()` 之后，变化有三点：

1. 数据类型变了  
   从图像对象变成了 PyTorch 的 Tensor，而且通常是 float32。

2. 数值范围变了  
   原来像素值是 0 到 255，转换后会缩放到 0 到 1。  
   例如原来某个像素是 128，转完大约是 0.50196。

3. 维度顺序变了  
   原来是 高 × 宽 × 通道，变成 通道 × 高 × 宽。  
   也就是 PyTorch 常用的格式。

所以 `img_tensor = trans_totensor(img)` 后，`img_tensor` 一般可以理解为：

- 类型：Tensor
- dtype：float32
- 形状：[3, H, W]
- 值域：[0, 1]

后面的 `trans_norm = transforms.Normalize(mean=[0.5, 0.5, 0.5], std=[0.5, 0.5, 0.5])` 是在这个基础上继续变换。它对每个通道做：

- 新值 = 原值 - 0.5，再除以 0.5

等价于：

- 0 会变成 -1
- 0.5 会变成 0
- 1 会变成 1

所以你打印的 `img_tensor[0][0][0]` 是 ToTensor 之后某个像素的原始值，而 `img_norm[0][0][0]` 是同一个位置经过标准化后的值。

解释一下归一化公式

GitHub Copilot:
我先把这个公式拆成“每个通道做了什么”和“为什么这样做”两部分，直接对你现在看到的 `Normalize` 逻辑解释清楚。归一化公式就是：

$$
\text{output[channel]} = \frac{\text{input[channel]} - \text{mean[channel]}}{\text{std[channel]}}
$$

意思是对每个通道单独做“减均值，再除标准差”。

在你这里，`mean=[0.5, 0.5, 0.5]`，`std=[0.5, 0.5, 0.5]`，所以每个 RGB 通道都按同样规则变换：

$$
x' = \frac{x - 0.5}{0.5} = 2x - 1
$$

因为 `ToTensor()` 之后像素已经从 $[0, 255]$ 变成了 $[0, 1]$，所以：

- 原来是 $0$，归一化后变成 $-1$
- 原来是 $0.5$，归一化后变成 $0$
- 原来是 $1$，归一化后变成 $1$

直观上，它是在把数据中心移到 0 附近，并把尺度缩放到比较统一的范围，这样模型训练通常更稳定、更快。

为什么img_norm2的图片是黑色

GitHub Copilot:
因为你这句：

```python
trans_norm2 = transforms.Normalize(mean=[1, 1, 1], std=[3, 2, 1])
```

把 `ToTensor()` 后本来在 $[0, 1]$ 的像素又整体往下减了 1。

所以每个通道都会变成：

$$
x' = \frac{x - 1}{\text{std}}
$$

而 $x$ 本来最多也就 1，所以：

- 第一通道：$(x-1)/3$，范围大概是 $[-0.333, 0]$
- 第二通道：$(x-1)/2$，范围大概是 $[-0.5, 0]$
- 第三通道：$x-1$，范围是 $[-1, 0]$

也就是说，`img_norm2` 里的值几乎全是 0 或负数。

而 `writer.add_image(...)` 显示图像时，负数通常会被截断成 0，0 就是黑色，所以你看到的就是一张几乎全黑的图。

简单说就是：

- `Normalize` 不只是“美化一下数据”，它会真的改数值范围
- 你这里的 `mean=1` 太大了，把图像整体压到 0 以下
- TensorBoard 显示时把这些负值当成黑色处理了

如果你想看到正常的效果，可以试这两种：

```python
trans_norm2 = transforms.Normalize(mean=[0.5, 0.5, 0.5], std=[0.5, 0.5, 0.5])
```

或者只把 `img_norm2` 打印出来看数值，不直接拿它当“可视化图片”。

如果你愿意，我可以顺手帮你解释一下为什么 `img_norm` 还能看起来正常，而 `img_norm2` 会黑得这么明显。
